# Approve a Personal Agent request

Need: a real OAuth request opened by the intended client, its target Server and request ID. Complete: the administrator approves that request and the original authorization page returns to the client. The client must then make an authenticated `list_connections` call.

1. Verify the request's Server, client, callback and time through the management API. On the authorization page, **Ask installation Agent → Copy request** copies its link; the link identifies the request but grants no permission.
2. [Check management access](../common/access.md), then return here. Browser login is optional: an Agent with Wrangler management access can approve without configuring a password or Passkey.
3. Read `agent-request --id REQUEST_ID` (or `agent-requests` to find it) with [admin.mjs](../common/commands.md). Use `agent-approve --id REQUEST_ID`; optionally add `--name NAME` to label the new connection. Otherwise the name comes from the OAuth client metadata. Every approved request creates a new connection, including reauthorization from the same client; names and OAuth client IDs never select an existing record.
4. Keep the original authorization page open. It checks approval automatically and returns to the client's validated callback. Management approval never needs to operate that browser. If a write response is lost, read the request before retrying.

Without Wrangler access, the user can choose **Approve yourself** on the original authorization page, sign in and approve there. If no browser login exists, **Set up browser login** lets the user get a setup link from a management Agent or choose **Verify with Cloudflare**; that entry resumes an unfinished verification when one exists. After setup, return to the same request and explicitly approve it. Setup alone is not approval. An already signed-in user approves directly, without choosing either tab.

The management page lists actual pending requests under **Personal Agents → Awaiting approval**. **Add** only supplies the connection prompt or MCP configuration. In the review dialog, the user can edit the connection name before approving; this does not change the OAuth client identity. Approval closes the dialog and adds a new row. After the client's first authenticated MCP request, returning to the management page or selecting **Refresh** shows **Connected**. Lists refresh after management actions and on focus, without periodic polling. Old connections remain independent and can be removed explicitly when no longer needed. An expired request offers a new prompt to send to the client; refreshing cannot renew it.

Cancelling on the original authorization page or rejecting in management ends the request. The original page automatically returns to the client's registered callback with `error=access_denied` and the original `state`; it does not close the browser. If completing that return fails, the page offers a retry. The management review dialog closes and its request leaves the pending list; an original page that was closed can resume this return while its request and browser binding remain valid.

Return to [Connect a Personal Agent](index.md#connect), or the client recipe you were following, to call `list_connections` and [continue after connection](index.md#after-connection). For a closed, expired or interrupted page, use [OAuth recovery](authorization.md#recover-an-interruption).
