# Connect this Mac's Codex

Run from local Codex on the Mac being added. Obtain the target Server URL from the user or preceding handoff; if no Server exists, continue [Server installation](../server/install.md). Local installation does not require Wrangler; check [management access](../common/access.md) when approval is needed and your environment may be able to provide it.

1. Install the target release's DotX Desktop package through Codex's normal plugin installation mechanism. Keep its installation identity; the same plugin handles first and later Macs. Do not modify app files, signatures, binaries or startup behavior.
2. Call device_status to obtain this plugin's host-provided data_dir, package version and actual owner state. If the installed tool is missing, follow [host loading recovery](../troubleshooting/index.md#the-installed-plugins-tool-is-missing) before configuring it. Read bundled docs under PLUGIN_ROOT. Never infer a home-directory path or use another plugin's storage.
3. Use the package's cli.mjs connect command with --state set to that exact data_dir and --url set to the selected Server. It generates/reads this installation's Ed25519 identity, initializes the native caller and submits a public-key application. Reuse an existing matching installation/application; missing or corrupt existing credentials are errors, not permission to generate replacements. A configured different service requires the explicit [reset/change-service flow](../maintenance/remove.md).
4. After connect returns, the loaded plugin picks up complete first-time configuration automatically. Call device_status again and allow the connection to initialize; verify the actual owner's target Server, device ID, signed connection and pending/approved state. Configuration being written is not this check. If the tool is missing, follow [host loading recovery](../troubleshooting/index.md#the-installed-plugins-tool-is-missing). If it reports a setup or connection error, diagnose that error rather than asking for a routine app restart.
5. If the request is pending, check Wrangler management access when available. Approve the matching request through the Server management tool; otherwise give /admin/devices and the exact device/application identity to the administrator. An already approved device needs no new approval. Only public-key approval by the service grants access. The plugin may remain authenticated and idle while pending; after approval the Server notifies it. No Codex calls run while pending.
6. Once approved, call `device_status` again and verify the local fields listed below. This completes the Codex stage without requiring a Personal Agent. If remote MCP is already available, also check this device in `list_connections`; otherwise leave the end-to-end check to Personal Agent connection. The plugin follows normal Codex host lifetime. An arbitrary stdio entry may be a standby; inspect the actual owner rather than treating standby as offline.

After submission and verifying the target connection, it is valid to finish this installation while awaiting approval; say what remains. If approval, plugin loading or target verification cannot be completed, hand it off explicitly. Offer the user's chosen [Personal Agent connection](../index.md), including additional Agents controlling this Server's approved devices. Finish with [handoff](../common/handoff.md).

Pending applications expire after 7 days. When the user requests connection again after an application expires, is rejected, or the device is revoked, run the same connect command. It preserves the device ID and key pair, creates a new application and still requires administrator approval. If the existing owner's connection has stopped following rejection or revocation, refresh the affected host MCP configuration to restart it; first-time configuration pickup does not restart a stopped, configured owner. Verify the current application and connection as above. Revocation does not automatically reapply or restore the old approval. Reset the identity only when explicitly replacing lost/compromised keys or changing service, following [removal and reset](../maintenance/remove.md).

## Local command and plugin loading

Resolve the installed package root from `device_status.docs_dir` (its parent) and use the exact `data_dir` returned by that tool. Run the package CLI with a Node version satisfying the release requirement:

```sh
node /ABSOLUTE/PLUGIN_ROOT/cli.mjs connect --state /EXACT/HOST_PLUGIN_DATA --url HTTPS_ORIGIN --name 'This Mac'
node /ABSOLUTE/PLUGIN_ROOT/cli.mjs status --state /EXACT/HOST_PLUGIN_DATA
```

The release ZIP contains a local marketplace at `.agents/plugins/marketplace.json`. In a Codex environment with the official CLI, register its extracted directory using `codex plugin marketplace add /ABSOLUTE/EXTRACTED_DESKTOP`, then install `dotx-desktop` from the `dotx` marketplace through the normal plugin UI. If native App Server tools are available, discover their current schemas: `plugin/install` accepts this marketplace file and plugin name, and `config/mcpServer/reload` refreshes that host's MCP configuration. These are host capabilities, not DotX replacement installation APIs. When they are unavailable, use the [host loading recovery](../troubleshooting/index.md#the-installed-plugins-tool-is-missing) sequence. Do not equate a missing refresh tool with a requirement to quit the whole app.

After installation or a host refresh, rediscover the MCP entry before calling `device_status`. Check `target_server`, `device_id`, `owner.connection.authenticated`, `owner.connection.approved`, the actual `owner.version` and the needed `owner.interfaces`. `entry.role` and `entry.diagnostic` describe that process's loaded state; an old entry can still read the approved current owner. Use the owner's connection and interfaces to assess readiness, not the entry role alone. `owner.connection.state=pending` means the signed identity is connected and awaits administrator approval; it does not mean an available execution device yet.

A refresh must affect the Codex host that will use this plugin. Reloading an independent CLI host does not prove that the Desktop host reloaded. Recheck the actual owner through the current host's `device_status`. Keep identity, configuration and lock state in the host-provided data directory; do not copy, edit or reset it to fix an unavailable native interface.

First-time configuration is read after the installation command releases its lock and the caller setup is complete. The existing plugin check runs every second; it does not impose a one-second connection deadline. Missing or incomplete setup keeps waiting; malformed configuration or a connector startup error requires explicit recovery. Once configuration has been loaded, file edits do not hot-switch the running installation. Updates and intentional reset/service changes still follow their own guides.
